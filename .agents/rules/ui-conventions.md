# UI conventions

- Leer `CONTEXT.md` y el briefing del proyecto en `docs/briefings/` antes de cambiar contenido o validaciones.
- Mantener separadas las apps de `uis/`; no importar componentes entre ellas.
- Usar los valores cerrados del briefing tal cual (países Estados Unidos / España, almacenes `LA` / `ZGZ`, categorías, sedes); no inventar opciones.
- Mantener copy profesional y orientado a operaciones; no hacer claims no verificables.
- Cada pantalla nueva debe tener estado vacio, error o carga si depende de datos remotos.
